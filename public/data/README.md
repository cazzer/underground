# Data sources

Each file group below comes from one source. The MTA GTFS files are generated by
`npm run data`, and `stations/` (the interiors and `index.json`) and `station-depths.json` by `npm run data:stations`; don't edit them by hand.

This project is not endorsed by the MTA. Data may not be real time and is not
guaranteed to be accurate.

## MTA GTFS

Static GTFS schedule data, https://www.mta.info/developers. Use is subject to the MTA's
terms and conditions: https://www.mta.info/developers/terms-and-conditions.

These files are derived, not copies of the feed: shapes are simplified (Douglas-Peucker,
3 m), segment run times are medians over the scheduled trips, and trip origins are
delta-encoded.

Route colors come from `routes.txt`. MTA's IP status for those colors is UNVERIFIED.

- `stations.json` (also see the NY Open Data section: its `borough`, `ada` and `adaPartial` fields)
- `routes.json`
- `shapes.json`
- `segments.json`
- `transfers.json`
- `trip-index.json`
- `timetable/<serviceId>.json` (derived: each service's stop_times regrouped by stop pattern, in 30 s
  units, plus the same-station `transfers.txt` rows; loaded on demand, outside the startup budget)

## OpenStreetMap (ODbL 1.0)

© OpenStreetMap contributors, available under the ODbL 1.0. See
`LICENSE-ODbL.md`.

- `stations/L08.json` and the generated `stations/<id>.json`
- `station-depths.json`
- `streets/<id>.json`
- `walk/<id>.json`

Per-station interior files (`stations/<id>.json`) merge hand-authored interiors with OSM
platform polygons. The whole file is marked as a derivative database under the ODbL; each
element's `sources` says where it came from, and elements whose `sources` include `nyopendata` are
MTA data under the OPEN-NY Terms of Use (the file's `attribution` says so, see below).
`station-depths.json` is packed from those files, hand-authored and generated alike (each station's
platform track runs and rail height, so the map's tracks can descend to the platform), and carries
the same license and the OSM and MTA credits; it adds an OPEN-NY line only when a rail height
comes from an E&E rise.

`streets/<id>.json` (one per station) is the OSM streets (named roadways within 300 m of the station point) and walking ways (footways, steps and paths, within 100 m), clipped,
simplified and packed (`npm run data:streets`), plus the station's entrances joined to the street they open onto. The
whole file is a derivative database under the ODbL; the entrance points are MTA data (NY Open Data i9wp-a4ja) under the
OPEN-NY Terms of Use, not ODbL, and each file's `attribution` says so. The files load on focus and sit outside the
startup budget.

The citywide basemap tiles (`/basemap/nyc.pmtiles`, a Protomaps build cut to the five boroughs, only the earth, water,
landuse and roads layers) are not in this directory or in git: they are built by `.github/workflows/basemap.yml`, copied in
at deploy, and an ODbL 1.0 derivative database under the same credit. Their licence notes are in the release text, and the
sources and terms in `docs/research/data-sources.md` §5.3.
`walk/<id>.json` (one per station) is the walkable graph of the same OSM ways within 300 m (sidewalks, crossings, steps, paths,
pedestrian streets and roads), packed as OSM node ids, decimeter coordinates and edges (`npm run data:walk`). The whole file is a
derivative database under the ODbL and carries the OSM credit only: the anchor is the station's `stations.json` point (MTA GTFS),
everything else is OSM. It sits outside the startup budget.

## NY Open Data / MTA Elevator and Escalator feeds

Attribution: Metropolitan Transportation Authority, https://www.mta.info/open-data.
These datasets carry no license field, so the OPEN-NY Terms of Use (2013-03-08) apply
(see `docs/research/data-sources.md` §5.1).

- MTA Subway Stations (dataset 39hk-dx4f, pinned in `data/stations/catalog/stations.json`) gives
  `borough`, `ada` and `adaPartial` in `stations.json`. MTA data under the OPEN-NY Terms of Use
  (2013-03-08), attributed to the Metropolitan Transportation Authority.
- Subway entrances and exits (dataset i9wp-a4ja) and the elevator and escalator asset inventory
  (94fv-bak7) feed entrance and elevator positions in `stations/*.json`. These elements have
  `nyopendata` in their `sources` and are MTA data under the OPEN-NY Terms of Use, not ODbL; the
  interior files' `attribution` carries that note. The entrance points in `streets/<id>.json` are the same
  entrance data, and those files' `attribution` carries the same split.

## Generated metadata

`stations/index.json` is generated by `npm run data:stations`: it lists the stations that have
an interior file and whether each is authored or generated. It holds no OSM or MTA content
(just station ids), so the licenses above don't apply to it.

## Hand-authored

Station interior layouts (levels, mezzanines, stairs) written for this project. The authored
inputs live in `data/stations/` and are not shipped; the merged result is in `stations/<id>.json`
(see the OSM note above).
